ORMO Manager 기획서

대상: 카페 운영자(사장님 또는 알바생). 아래는 기획 초안의 워크플로우를 그대로 따르고, 각 항목에 현재 앱의 구현 상태를 붙인 문서입니다.

  • ✅ 구현됨 / ⚠️ 구현돼 있지만 초안과 다름 / ⬜ 미구현 / 💬 논의 필요 / 🔌 BE가 있어야 완성
  • 이 표기가 붙은 항목의 상세는 마지막 장 "남은 기능"에 있습니다.

II. ORMO Manager

기본 워크플로우

1. 로그인

  • 1-1. 매장 하나당 하나의 계정을 관리자 측에서 발급하여 지급한다. — ✅ 앱에는 회원가입이 없고 아이디/비밀번호 로그인만 있습니다. 발급은 관리자 측(BE) 몫입니다.
  • 1-2. 일반회원과 다르게, 2차 비밀번호도 존재한다. (매출 조회 등에서만 사용) — ⚠️ 매출 조회 외에 메뉴 추가·삭제·수정, 설정에도 걸려 있습니다.
  • 1-3. 동시 접속 절대 불가하다. — ⬜🔌 BE가 세션을 하나만 허용해야 하고, 앱에는 세션이 끊겼을 때의 처리가 없습니다.

2. 매장 상태 변경

  • 2-1. 영업중, 일시정지, 마감 3가지 단계가 있다. — ✅ 상단 컨트롤에서 변경합니다. 일시정지는 재개 시간(10/20/30/60분, 직접 해제)과 사유(주문 혼잡/재료 준비/휴식)를 고릅니다.
  • 2-2. 로그인 시, 로그아웃 시 마감 상태로 강제 변경된다. — ⬜ 로그인/로그아웃해도 매장 상태가 그대로입니다.
  • 2-3. 영업중 상태에서만 신규 주문을 받을 수 있다. — 🔌 신규 주문은 BE가 걸러야 합니다. 앱은 상태를 저장하고 표시만 합니다.
  • 2-4. 일시정지 상태에서는 기존 주문을 처리할 수는 있으나, 신규 주문은 들어오지 않는다. 사용자에게 매장 상태를 어떻게 보여줄지는 논의사항이다. — ✅ 기존 주문 처리는 가능합니다. 💬 고객 앱 표시 방식은 미정입니다.
  • 2-5. 마감 상태로 전환하기 위해서는 모든 주문이 처리된 상태여야 한다. — ⚠️ 미처리 주문이 있어도 확인창을 거치면 마감됩니다.

3. 주문 관리 탭

  • 3-1. 접수 대기, 제조 중, 픽업대기로 나뉘어 있다. — ✅ 3열 보드입니다.
  • 3-2. 각 상태의 모든 카드에는 아래 정보를 제공한다.
    • 3-2-1. 주문번호, N분 전, 주문자 닉네임, 메뉴 정보 및 옵션, 수량, 개별 금액 및 총 금액 — ✅ 닉네임 대신 customerName(이름)을 표시합니다. 💬 표시 이름 정책 확인 필요.
  • 3-3. 접수 대기는 사용자가 매장에 요청 후 처리되지 않은 주문이 있으며, FIFO 구조로 설계. — ✅ 접수 시각 오름차순.
    • 3-3-1. 각 카드에 자동 거절까지 MM:SS(10분 고정), 부분취소 허용 여부를 추가로 표시 — ✅ 2분 이하이면 빨갛게 표시됩니다. 자동 거절은 앱이 임시로 처리하고 있어서 BE에서 처리해야 합니다(🔌).
    • 3-3-2. 거절, 수락이 있고, 부분취소 허용 주문건일 경우 일부 메뉴만 취소 후 수락 가능하다. — ✅ 메뉴 줄 단위로 취소합니다.
    • 3-3-2. 거절 또는 일부 메뉴만 취소 시, 사유를 선택한다. (재료 소진, 주문 폭주, 가게 사정 中 1) — ⚠️ 거절은 사유를 고르지만(✅), 일부 메뉴만 취소는 사유 선택이 없습니다(⬜).
  • 3-4. 제조 중은 수락된 주문 건을 수락한 순서대로 표기한다. (FIFO) 조리 완료된 경우 조리 완료 버튼을 통해 완료 처리할 수 있다. — ⚠️ 조리 완료는 ✅, 정렬은 수락 순서가 아니라 접수 시각 순입니다.
  • 3-5. 픽업대기는 매장에서 지정한 시간에 따라 자체 폐기 시간 카운터를 가동한다. 지정한 시간은 하단에 다시 언급된다. — ✅ 조리 완료 후 경과 시간과 폐기 가능까지 남은 시간을 표시하고, 가능해지면 자체 폐기가 켜집니다. 시간은 설정에서 10~30분(기본 20분), 마감 상태에서만 수정합니다.
  • 3-6. 우측 상단에 오늘 처리 내역을 보여준다. — ✅ 각 건의 금액도 표시합니다.
    • 3-6-1. 오늘 들어온 주문 중 처리된 건에 대하여 주문번호 또는 이름으로 검색할 수 있다. — ✅
    • 3-6-2. 전체, 픽업 완료, 거절 및 취소, 미수령 건을 필터링하여 볼 수 있다. — ✅ 건수도 함께 표시합니다.
    • 3-6-3. 이 중 픽업 완료 건에 대하여 환불을 진행할 수 있다. — ✅ 메뉴별 수량 단위 부분 환불, 2차 비밀번호 없음. 환불 사유와 이력은 ⬜.

4. 메뉴 관리 탭

  • 4-1. 가게 내 메뉴를 카테고리에 따라 분류하여 조회할 수 있다. — ✅ 에스프레소/논커피/티/디저트 탭.
  • 4-2. 특정 메뉴를 클릭하면 … — 초안이 여기서 끊겨 있습니다. 현재 앱은 메뉴 카드를 누르면 수정(2차 비밀번호) / 품절 처리·판매 재개가 나옵니다.

초안에 없지만 앱에 구현된 기능

  • 주문 처리 보조: 조리 완료/픽업 완료 15초 실행 취소, 거절 사유가 재료 소진일 때 해당 메뉴 함께 품절 처리, 쿠폰 주문 표시(카드/쿠폰 금액 분리).
  • 새 주문 알림: 알림음을 처리할 때까지 7초마다 반복, 상단 배너, 알림음 켜기/끄기.
  • 영업: 영업시간 도래 시 "영업을 시작할까요?" 안내, 영업시간 종료 시 자동 마감, 일시정지 자동 재개.
  • 메뉴: 카테고리를 넘나드는 일괄 품절/판매 재개, 메뉴 추가·삭제.
  • 매출 조회(2차 비밀번호): 일별/월별, 카드·쿠폰 구분, 월별 수수료와 예상 정산 금액, 메뉴별 소계.
  • 설정: 알림음, 비밀번호/2차 비밀번호 변경, 영업시간, 자체 폐기 시간.
  • 기기: 화면 꺼짐 방지, 인터넷 끊김 배너, 가로 고정.

상세 동작은 FEATURE_SPEC에 있습니다.

ORMO Manager 남은 기능

기획 초안(II. ORMO Manager)과 현재 앱 코드를 대조해 아직 구현되지 않았거나 초안과 다르게 동작하는 것만 모았습니다. 앱은 전부 mock 상태이고 BE 연동 전입니다.

  • 표기: 미구현 아직 없음 / 불일치 구현돼 있지만 초안과 다르게 동작 / 논의 정책이 정해지지 않음 / BE BE가 있어야 완성됨
  • 번호는 기획 초안의 번호를 따릅니다. 초안에 없는 항목은 +로 붙였습니다.

A. 기획 초안과 현재 앱이 다른 곳 (먼저 결정 필요)

1. 로그인

  • 1-2. 불일치 초안은 2차 비밀번호를 "매출 조회 등"에만 쓴다고 되어 있습니다. 앱은 매출 조회 외에 메뉴 추가·삭제·수정, 설정(비밀번호 변경, 2차 비밀번호 변경, 영업시간, 자체 폐기 시간) 에도 겁니다. 이 범위를 초안대로 줄일지, 앱 범위를 기획서에 반영할지 정해야 합니다.
  • 1-3. [미구현][BE] 동시 접속 불가. 앱에는 다른 기기에서 로그인되어 현재 세션이 끊겼을 때의 처리(강제 로그아웃 화면, 안내 문구)가 없습니다. BE가 세션을 하나만 허용하고, 앱이 끊김 신호를 받아야 합니다.

2. 매장 상태

  • 2-2. 미구현 로그인·로그아웃 시 마감으로 강제 변경. 현재는 로그인/로그아웃해도 매장 상태가 그대로입니다(LOGIN/LOGOUT 액션이 계정만 바꿈). 로그아웃 시 미처리 주문이 있을 때 어떻게 할지(막을지, 경고만 할지)도 같이 정해야 합니다.
  • 2-4. 논의 일시정지 중 고객 앱에 매장 상태를 어떻게 보여줄지. 앱은 사유(주문 혼잡/재료 준비/휴식)와 재개 시각을 이미 갖고 있으니, 고객에게 사유와 예상 재개 시각을 보여줄지만 정하면 됩니다. 값 전달은 BE 몫입니다.
  • 2-5. 불일치 마감은 모든 주문이 처리된 상태에서만 가능해야 합니다. 현재는 미처리 주문이 있어도 확인창("접수 대기 N건…")만 거치면 마감되고, 마감 후에도 기존 주문 처리는 계속됩니다. 초안대로면 확인창 대신 마감 차단(미처리 건수 안내 + 주문 처리 유도)으로 바뀌어야 합니다. 같이 정할 것:
    • 자동 마감(영업시간 종료)에 미처리 주문이 있으면? 지금은 그냥 마감됩니다.
    • 픽업 대기(READY) 주문도 "미처리"로 보는지. 그렇다면 고객이 가져가지 않은 주문은 자체 폐기 가능 시간이 되기 전까지 마감이 막힙니다.

3. 주문 관리

  • 3-3-2. 미구현 일부 메뉴만 취소 시 사유 선택. 거절은 사유(재료 소진/주문 폭주/매장 사정)를 고르지만, 부분 취소는 사유 없이 바로 취소됩니다. 주문 데이터에도 부분 취소 사유 필드가 없습니다(Order.rejectReason은 거절 전용).
  • 3-4. 불일치 제조 중은 수락한 순서(FIFO)로 보여야 합니다. 현재는 주문 접수 시각(createdAt) 순입니다. 수락 시각 필드(acceptedAt)가 없어서, 먼저 들어왔지만 나중에 수락한 주문이 위로 올라옵니다.
  • 3-2-1. 확인 초안은 "주문자 닉네임"인데 앱은 customerName(이름)으로 표시하고, 오늘 처리 내역의 검색도 이름 기준입니다. 고객 앱이 닉네임을 쓰는지, 실명을 쓰는지 정해야 합니다(실명이면 마스킹 항목 참고).

4. 메뉴 관리

  • 4-2. 확인 초안이 "특정 메뉴를 클릭하면"에서 끊겨 있습니다. 현재 앱은 메뉴 카드를 누르면 수정(PIN) / 품절 처리·판매 재개 시트가 뜹니다. 이어질 내용을 알려주시면 대조하겠습니다.

B. 아직 없는 기능

영업

  • +1. 미구현 요일별 영업시간·정기 휴무일. 지금은 하루 한 구간(openTime~closeTime)만 있고 자정을 넘기는 시간은 지원하지 않습니다.
  • +2. 미구현 마감 후 정리 절차. 마감 시 남은 미수령 주문을 한 번에 폐기·정리하는 흐름이 없습니다(2-5 결정과 연결됨).
  • +3. [미구현][BE] BE 연결 상태 표시. 지금의 "연결 끊김" 배너는 기기의 인터넷 상태만 봅니다. 서버와 실제로 통신 중인지(heartbeat)는 모릅니다. 주문이 안 들어오는 상황을 매장에서 알아챌 수 있게 하려면 필요합니다.

주문·환불

  • +4. 미구현 환불 사유 입력과 환불 이력 목록. 지금은 사유 없이 환불되고, 환불은 주문 단위 합계만 남습니다(언제, 누가, 몇 개를 환불했는지 기록 없음).
  • +5. 미구현 어제 이전 주문의 환불. 오늘 처리 내역에 보이는 당일 주문만 환불할 수 있습니다. 허용 기간(예: 7일)을 정하면 매출 날짜 기준 문제도 같이 정해야 합니다(+15).
  • +6. 미구현 부분 취소를 수량 단위로. 지금은 메뉴 줄 단위로만 취소합니다(2잔 중 1잔만 취소 불가). 환불은 수량 단위입니다.
  • +7. 미구현 짧은 픽업번호. 주문번호가 BW-114068처럼 길어서 고객이 말로 전하기 어렵습니다.

보안

  • +8. [미구현][BE] 2차 비밀번호 무조작 자동 재잠금. 현재 설정 화면은 한 번 풀면 화면에 머무는 동안 계속 열려 있고, 매출 조회는 화면을 벗어나야 다시 잠깁니다. 일정 시간 무조작이면 다시 잠그는 동작이 없습니다.
  • +9. [미구현][BE] 2차 비밀번호 시도 횟수 제한. 지금은 앱에서 비교하고 횟수 제한이 없습니다. 서버 검증으로 옮길 때 같이 필요합니다.
  • +10. 미구현 고객 이름 마스킹. 주문 카드와 처리 내역에 이름이 그대로 보입니다(3-2-1 결정과 연결됨).
  • +11. 미구현 권한 구분. 계정당 2차 비밀번호가 하나이고 점주/직원 구분이 없습니다. 환불에 PIN을 걸지 않기로 했으므로, 직원이 환불할 수 있는 상태입니다.

메뉴

  • +12. 미구현 메뉴 숨김 vs 삭제. 지금 삭제는 확인창 없이 즉시 지워지고 되돌릴 수 없습니다.
  • +13. 미구현 "오늘만 품절"과 "판매 중단"의 구분. 품절은 직접 풀 때까지 유지됩니다.
