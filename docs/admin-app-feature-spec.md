# ORMO 관리자 앱 기능 명세 (현재 코드 기준)

BE 코드베이스와 대조하기 위해 현재 앱 코드에서 추출한 명세입니다.

- 범위: 매장 점주용 태블릿(가로) 앱. 계정은 지점당 1개, 회원가입 없음.
- 데이터는 전부 로컬 mock 상태(React Context)이며 BE 연동은 아직 없습니다. 아래 "BE가 맡아야 할 일"은 앱 코드에서 역으로 추론한 것입니다.
- 표기: **[앱]** 앱 안에서 동작이 구현된 것 / **[mock]** BE가 생기면 제거될 임시 동작 / **[가정]** 앱이 임의로 정한 규칙(BE 확인 필요).
- 코드 위치는 `src/` 기준입니다.

## 1. 도메인 모델

## 2. 인증 · 2차 비밀번호

- 로그인: 아이디 + 비밀번호만. 실패 시 "아이디 또는 비밀번호가 올바르지 않습니다." 회원가입, 지점 선택 화면 없음. 로그인 상태는 앱 메모리에만 있습니다(자동 로그인 없음). 비밀번호는 현재 평문 비교입니다 [mock].
- 2차 비밀번호(PIN, 숫자 4자리) 입력창: 4자리가 차면 즉시 검증, 틀리면 점이 붉어지고 입력 초기화. 시도 횟수 제한이나 잠금은 없습니다. 검증을 앱 안에서 합니다 [mock].
- **PIN이 필요한 곳**
  - 메뉴: `메뉴 관리`(추가/삭제 창 열기), `수정`
  - `매출 조회` 화면 전체(들어갈 때 1회, 화면을 벗어나면 다시 잠김)
  - 설정: 비밀번호 변경, 2차 비밀번호 변경, 영업시간 수정, 자체 폐기 시간(설정 화면에 머무는 동안 1회만 입력)
- **PIN이 필요 없는 곳**: 주문 수락/거절/조리 완료/픽업 완료/자체 폐기/부분 취소, **환불**, 영업 상태 변경, 품절 처리·해제(일괄 포함), 알림음 설정, 오늘 처리 내역 조회.
- 비밀번호 변경: 현재 비밀번호 확인, 새 비밀번호 6자 이상, 확인 입력 일치.
- 2차 비밀번호 변경: 현재 PIN 확인, 새 PIN 숫자 4자리, 확인 입력 일치.

## 3. 주문 관리 (`app/dashboard/index.tsx`)

화면은 3열 보드입니다: **접수 대기(REQUESTED) / 제조중(MAKING) / 픽업 대기(READY)**. 정렬은 접수 대기·제조중은 `createdAt` 오름차순, 픽업 대기는 `readyAt` 오름차순입니다.

### 3.1 상태 전이 (`lib/order.ts`)
```
REQUESTED → MAKING | REJECTED | CANCELED(고객 취소, 앱에 버튼 없음)
MAKING    → READY
READY     → COMPLETED | UNCLAIMED
COMPLETED / REJECTED / CANCELED / UNCLAIMED → (종료)
```
- 허용되지 않은 전이는 reducer에서 무시합니다(더블 탭, 수락 후 취소 방지).
- **수락 후에는 누구도 취소할 수 없습니다**(운영 결정).

### 3.2 주문 카드
주문번호, 경과 시간("N분 전"), 고객 이름, 메뉴 줄(수량 박스 + 메뉴명 + 옵션 칩 + 줄 금액), 합계 금액.
- 수량 2 이상은 파란 박스로 강조. 부분 취소된 줄은 취소선.
- REQUESTED: 부분 취소 정책 배지(허용/전체 취소), "자동 거절까지 mm:ss"(2분 이하 빨강 + 카드 빨간 테두리).
- 쿠폰 주문: "음료 교환권 사용"/"금액권 사용" 배지, "카드 ○원 · 쿠폰 ○원" 표시.
- READY: "준비 완료 후 N분", 자체 폐기까지 남은 시간 / 가능해지면 주황 테두리 + 경고.
- 부분 취소가 있으면 "부분 취소 환불 ○원" 표시, 합계는 환불을 뺀 금액입니다.

### 3.3 동작
| 동작 | 조건 | 결과 |
|---|---|---|
| 수락 | REQUESTED | MAKING. 확인창 없음, 토스트 |
| 거절 | REQUESTED | 사유 선택 필수 → REJECTED. 결제 전액 취소(쿠폰은 복원)를 안내하고 되돌릴 수 없다는 문구를 보여줌 |
| 일부 메뉴만 취소 | REQUESTED + `ALLOW_PARTIAL` + 남은 메뉴 2줄 이상 | 선택한 **줄 단위**(수량 단위 아님)로 `canceled=true`. 전체를 취소하려면 거절을 쓰라고 안내. 되돌릴 수 없음 |
| 조리 완료 | MAKING | READY, `readyAt` 기록 |
| 픽업 완료 | READY | COMPLETED |
| 자체 폐기 | READY + 현재 ≥ (`readyAt` + `discardAfterMinutes`) | UNCLAIMED. 확인창, 되돌릴 수 없음 |

- `CANCEL_ALL` 정책 주문에는 부분 취소 버튼이 없고 "일부 메뉴를 만들 수 없으면 거절(전체 취소)해 주세요." 안내가 나옵니다.
- **거절 사유**(선택지 3개, 순서 고정): 재료 소진 → 주문 폭주 → 매장 사정. `TIMEOUT`(접수 시간 초과)은 시스템 전용. 재료 소진을 고르면 그 주문의 메뉴 중 함께 품절 처리할 메뉴를 고를 수 있고, 거절과 품절 처리가 한 번에 반영됩니다.
- **실행 취소**: `조리 완료`(READY→MAKING)와 `픽업 완료`(COMPLETED→READY)만 가능. 토스트 버튼은 5초 동안 보이고, 앱이 처리한 시각(`updatedAt`) 기준 15초가 지나면 거부합니다. 환불 이력이 있는 주문은 불가. 수락/거절/자체 폐기는 불가.
- **접수 시간 초과 자동 거절**: 10분(`ORDER_ACCEPT_TIMEOUT_MINUTES`). `expiresAt`이 지난 REQUESTED 주문을 앱이 1초마다 확인해 `REJECTED(TIMEOUT)`로 바꾸고 토스트를 띄움 **[mock]**. BE가 처리하면 앱은 상태만 받습니다.

### 3.4 오늘 처리 내역 (`components/recent-orders-modal.tsx`)
- 대상: 해당 매장 주문 중 상태가 `COMPLETED` `UNCLAIMED` `REJECTED` `CANCELED`이고 **`createdAt`이 오늘인 것**. 최신 처리(`updatedAt`) 순.
- 표시: 주문번호 · 이름, 메뉴(옵션 포함, 환불된 수량 표기), **금액**(취소/거절은 원금액 취소선, 환불이 있으면 "환불 -○원"), 상태 라벨(픽업 완료 / 미수령 폐기 / 고객 취소 / 자동 거절 / 거절 · 사유), 처리 시각.
- 검색: 주문번호 또는 이름. 필터: 전체 / 픽업 완료 / 거절·취소 / 미수령(건수 표시).

### 3.5 픽업 후 환불 (`components/refund-modal.tsx`)
- **조건**: `COMPLETED`이고 환불 가능한 수량이 남은 주문(오늘 처리 내역 목록의 `환불` 버튼). 미수령/거절/취소 주문은 불가.
- **2차 비밀번호 없음.**
- 메뉴별로 환불 수량을 −/+로 선택(최대 = `qty - refundedQty`, `canceled` 줄 제외), `전체 선택/선택 해제`. 환불 금액 / 환불 후 주문 금액 표시. 쿠폰 주문이면 "카드 ○원 · 쿠폰 ○원(복원)"으로 나눠 보여줌.
- 이후 한 번 더 확인("○원을 환불할까요?") → 완료 시 토스트, 처리 내역 목록으로 복귀.
- 같은 주문을 여러 번 부분 환불할 수 있고, 다 환불하면 환불 버튼이 사라집니다.
- 환불 사유 입력, 기간 제한(오늘 주문만 보임), 환불 이력 목록은 없습니다.
- 환불 후에는 `netTotal = totalPrice - 부분취소금액 - 환불금액`이고, 전액 환불된 주문은 매출 건수·평균에서 빠집니다.
- 카드/쿠폰 안분은 쿠폰 금액 × 환불액 ÷ 총액으로 **비례 계산**합니다 [가정]. BE가 정확한 분할을 내려줘야 합니다.

## 4. 영업 상태 · 영업시간 (`components/store-status-control.tsx`, `store-schedule.tsx`)

- 상단 컨트롤: `영업중` / `일시정지` / `마감`. 상태를 바꾸면 이전의 일시정지 정보가 지워집니다.
- **일시정지**: 재개 시간(10/20/30/60분 또는 "직접 해제") + 사유(주문 혼잡 `BUSY` / 재료 준비 `PREP` / 휴식 `BREAK`). 상단에 "사유 · mm:ss 후 자동 재개" 표시. `pausedUntil`이 지나면 앱이 자동으로 OPEN으로 바꾸고 토스트 **[앱, BE도 같은 규칙 필요]**.
- **마감**: 처리하지 않은 주문(접수 대기+제조중+픽업 대기)이 있으면 건수를 보여주는 확인창. 마감해도 기존 주문 처리는 계속 가능("새 주문은 받지 않지만").
- **자동 마감**: 시계가 `closeTime`을 **넘어가는 순간**(5초 간격 확인) 상태가 CLOSED가 아니면 CLOSED로 바꾸고 토스트. 이후 점주가 수동으로 열면 그대로 유지됩니다(넘어가는 순간만 판정). 자정을 넘기는 영업시간은 지원하지 않습니다(분 단위 시각이 이전보다 작아지면 판정 건너뜀).
- **자동 개점 없음**: `openTime`을 넘어가는 순간(또는 앱 시작 시 CLOSED인데 영업시간 안) "영업 시작 시간입니다. 영업을 시작할까요?" 배너 → `영업 시작` / `나중에`.
- 영업시간 수정(설정, PIN): `HH:MM` 형식, `openTime < closeTime`(문자열 비교). **요일별 시간/휴무일 없음**.

## 5. 메뉴 관리 (`app/dashboard/menu.tsx`)

- 카테고리 탭(에스프레소/논커피/티/디저트) 안에 카드 그리드: 이름, 설명(2줄), 가격, HOT 배지, 판매중/품절 배지(품절은 흐리게).
- 카드 탭 → 액션 시트: `수정`(PIN) / `품절 처리`·`판매 재개`(PIN 없음).
- `메뉴 관리`(PIN) 창: 현재 카테고리에 메뉴 추가(메뉴명·설명·가격, 이름과 가격 필수) + 등록된 메뉴 삭제(삭제 확인 없음, 즉시 삭제).
- `수정`(PIN): 이름/설명/가격만 수정. 카테고리 이동, 이미지, 옵션(온도/사이즈) 관리, `isHot` 수정은 없습니다.
- **일괄 품절**: 선택 모드에서 카드를 여러 개(카테고리를 넘나들며) 선택, `이 카테고리 전체 선택`, `품절 처리` / `판매 재개`. 품절 처리 시 접수 대기 주문에 해당 메뉴가 있으면 "접수 대기 주문 N건에 ... 포함" 경고 토스트(주문은 자동으로 바뀌지 않음).
- 품절은 날짜/시간 제한 없이 직접 풀 때까지 유지됩니다("오늘만 품절"과 "판매 중단" 구분 없음). 신규 메뉴는 항상 `soldOut=false`, `isHot=false`로 생성됩니다.

## 6. 매출 조회 (`app/dashboard/sales.tsx`, `components/sales/*`, `lib/sales.ts`) — PIN 필요

### 6.1 집계 규칙
- **매출 주문** = 상태가 `COMPLETED` 또는 `UNCLAIMED`이고 환불 반영 후 금액(`netTotal`)이 0보다 큰 주문. 즉 **미수령 폐기 주문은 매출에 포함** [가정: 결제는 유지, 환불 없음].
- 주문 금액 = `totalPrice - 수락 전 부분 취소 금액 - 픽업 후 환불 금액`.
- 카드분/쿠폰분 = 쿠폰 금액 비례 안분(`paymentSplit`). 총 매출 = 카드분 + 쿠폰분. 평균 객단가 = 매출 ÷ 건수(반올림).
- **날짜 기준은 `createdAt`(주문 시각)**입니다. 처리/완료 시각이 아닙니다.
- 메뉴별 소계: 메뉴명 기준 수량·금액 합산(부분 취소·환불 수량 제외), 수량 내림차순.

### 6.2 일별
날짜 이동(◀ ▶, 오늘), 달력으로 날짜 선택(미래 선택 불가). 통계 3개(총 매출 + 카드/쿠폰, 주문 건수, 평균 객단가). 주문 내역 필터 `처리 완료`(기본) / `취소`(거절+고객 취소) / `미수령` / `전체보기`, 10건씩 `더보기`. 행: 주문번호, 메뉴, 시각, 쿠폰 배지, 상태 배지(고객 취소/자동 거절/매장 거절/미수령 폐기/부분 취소/부분·전액 환불), 금액. 메뉴별 소계 표.

### 6.3 월별
통계 3개 + **수수료**(`commissionRate`, 카드분/쿠폰분 따로 반올림해 합산) + **예상 정산 금액**(= 월 매출 − 수수료, **월별 화면에만** 표시). 쿠폰 매출에도 같은 수수료율을 적용하고 카드분/쿠폰분을 구분해 보여줍니다. 달력 칸에는 일 매출 약식 금액. 날짜 탭 → 그날의 통계 창 → `자세히 보기`로 일별 화면 이동.

## 8. 알림 · 기기 동작

- **새 주문 알림**: 로그인 이후 새로 생긴 REQUESTED 주문마다 알림음을 즉시 재생하고, `확인`을 누르거나 주문을 처리할 때까지 7초마다 반복합니다. 상단 배너 "새 주문 N건이 도착했습니다". 로그인 시점에 이미 있던 대기 주문은 울리지 않습니다. 알림음이 꺼져 있으면 배너만 표시합니다. 무음 모드에서도 재생하도록 오디오 모드를 설정합니다(실기기 미검증).
- **연결 끊김 배너**: `isConnected === false` 또는 `isInternetReachable === false`이면 "새 주문을 받을 수 없으니 와이파이를 확인해 주세요" 배너, 복구되면 토스트. 이 판정은 기기 인터넷 상태 기준이며 BE 연결(heartbeat) 확인은 아닙니다.
- **화면 꺼짐 방지**: 로그인 상태(대시보드)에서 `expo-keep-awake`로 항상 켜 둠.
- **토스트**: 수락/조리 완료/픽업 완료/거절/품절/환불/영업 상태 변경 등. 최대 3개 쌓임.
- **가로 고정**: `orientation: landscape`, iPad는 전체 화면 필수, 라이트 테마 전용.

## 9. BE가 맡아야 할 일 (앱 코드에서 추론)

아래는 앱이 현재 mock으로 대신하고 있는 동작입니다. BE 명세와 대조할 항목입니다.

1. **인증**: 로그인(아이디/비밀번호 → 지점 계정), 비밀번호 변경, **2차 비밀번호 검증·변경**(검증을 서버에서, 실패 횟수 제한 필요), 토큰 관리.
2. **주문 수신/푸시**: 새 주문을 실시간으로 앱에 전달(WebSocket/FCM 등), 주문 상태 변경 API(수락, 거절+사유, 부분 취소(줄 단위), 조리 완료, 픽업 완료, 자체 폐기, 실행 취소, 픽업 후 환불(줄+수량)).
3. **서버 측 규칙 강제**: 상태 전이 검증, 수락 후 취소 금지, 접수 10분 초과 자동 거절(+결제 취소), 자체 폐기 가능 시간(`readyAt + discardAfterMinutes`) 검증, 부분 취소 정책(`ALLOW_PARTIAL`일 때만), 환불 가능 수량 검증, 실행 취소 허용 시간(15초) 검증.
4. **결제 처리**: 거절/부분 취소/환불 시 카드 환불 + 쿠폰 복원(카드분/쿠폰분 정확한 안분), 수수료율(`commissionRate`) 제공.
5. **영업 상태**: 상태/일시정지(기한, 사유)/영업시간을 서버에 저장하고 같은 규칙(자동 마감, 일시정지 자동 재개)을 서버도 적용. 앱의 자동 처리는 태블릿 쪽 보조입니다. 고객 앱의 주문 가능 여부 반영.
6. **메뉴**: 메뉴 목록/추가/수정/삭제/품절 일괄 변경 API, 카테고리 enum, `isHot` 컬럼.
7. **자체 폐기 시간 연동**: 매장별 값(10~30분, 기본 20분)을 저장하고 고객 앱에 전달. 값이 바뀌면 기존 READY 주문에 적용할지 정책 결정 필요(앱은 현재 매장 값으로 즉시 재계산).
8. **매출 조회 API**: 기간(일/월)별 주문, 취소/미수령/환불 반영 집계. 일별 달력 일 매출, 월별 수수료/예상 정산.
9. **mock 제거 대상**: `OrderTimeoutWatcher`(자동 거절), `simulateIncomingOrder`(개발용 "테스트 주문 받기" 버튼, `__DEV__` 전용), `StoreSchedule`의 로컬 자동 마감/재개, 로컬 PIN 검증, 로컬 데이터(`data/mock.ts`).

## 10. 앱이 임의로 정한 규칙 (BE와 어긋날 수 있는 곳)

- 미수령 폐기(UNCLAIMED) 주문을 **매출 포함**으로 집계.
- 매출·처리 내역의 날짜 기준이 **주문 시각(`createdAt`)**. 환불은 환불한 날이 아니라 원주문 날짜의 매출에서 차감됩니다.
- 쿠폰 포함 주문의 카드/쿠폰 안분을 **비례 계산**. 수수료는 쿠폰 매출에도 동일 적용(운영 결정).
- 환불은 "오늘 처리 내역"에 보이는 **당일 주문만** 가능, 사유 입력 없음, PIN 없음.
- 부분 취소는 줄 단위(수량 단위 아님), 환불은 줄 + 수량 단위.
- 영업시간은 하루 한 구간(자정 넘김 불가), 요일별/휴무일 없음.
- 2차 비밀번호는 계정당 1개, 권한 구분(직원/점주) 없음.
- 알림음 설정은 서버가 아니라 기기별 로컬 저장.
